# Known Issues and Audit Findings

Audit of `main` at `78f3302` on 2026-11-14 (static review; nothing was built or run). Read the
entries for your area before you change it. When you fix one, delete its row and name the fix in
`CHANGELOG.md`. "Verify" means the finding comes from reading the code and needs a check in the
running app.

| ID | Severity | Area | Finding | Where |
|---|---|---|---|---|
| KI-01 | High | Amnezia gateway | The default API gateway is still Amnezia's (`http://gw.amnezia.org:80/`). Every "Amnezia Premium / Free" page (`PageSetupWizardApiServicesList`, `PageSettingsApi*`), store purchases, news and the services catalog therefore send CoCo users to Amnezia's commercial service under the CoCo brand. Owner decision needed: hide these flows, or replace them with webpack.ir services (`docs/integration/WEBPACK.md`, roadmap P1). | `client/core/repositories/secureAppSettingsRepository.cpp:20`, `client/core/controllers/api/*`, `gatewayController.cpp` |
| KI-02 | High | Updates | The update check reads `downloadBaseUrl` / `releasePageUrl` from the Amnezia gateway but builds the file name as `CoCoVPN_%1_windows_x64.exe`, so it either finds nothing or points at Amnezia's release page. The macOS / Linux patterns are still `AmneziaVPN_*`, and the store links are Amnezia's App Store id and Play package. CoCo needs its own update feed (for example a signed JSON on `iranux.site` or webpack.ir). Verify. | `client/core/controllers/updateController.cpp` |
| KI-03 | Medium | Batch accounts | `createNextBatchAccount` calls `ExportController::generate*Config` synchronously on the GUI thread, one SSH round trip per account and protocol, with only a 50 ms `QTimer` between steps. Large batches likely freeze the window between ticks, and a cancel is not possible. Move the batch into a worker (`QtConcurrent` + `QFutureWatcher`, as `InstallUiController` does) with a cancel flag. Verify on Windows. | `client/ui/controllers/selfhosted/exportUiController.cpp:147` |
| KI-04 | Medium | Layering, tests | `ExportUiController` (about 800 lines) mixes persistence of account groups and templates (`Sharing/*` keys), HTML / TXT rendering with tag replacement, file-name rules and batch orchestration inside a UI adapter. None of it has a test. Extract `AccountGroupsRepository`, `ShareTemplateRenderer` (pure, testable) and `AccountBatchController` into `client/core/`, then add Qt tests for rendering and file names. | `client/ui/controllers/selfhosted/exportUiController.*` |
| KI-05 | Medium | Account data | Account groups store each method's full client config in `Sharing/accountGroups` on one device only. They are included in settings backups (`m_fieldsToBackup` has `Sharing/`), but a revoke on the server (`revokeConfig`) or a change from another device does not update the group, so a shared page can show a config that no longer works. Verify. | `exportUiController.cpp`, `client/secureQSettings.h:47` |
| KI-06 | Medium | CI | `deploy.yml` (upstream's multi-platform matrix) runs on every push to a non-`main` branch and fails (missing secrets, self-hosted `android-runner` labels that this repository does not have). Since this PR it skips documentation-only pushes. Decide: trim it to the platforms CoCo ships, or disable it. `tag-deploy.yml` / `tag-upload.yml` are not adapted to CoCo. | `.github/workflows/deploy.yml` |
| KI-07 | Medium | CI | No CI job runs the Qt tests (`AMNEZIA_BUILD_TESTS: OFF` in `windows-build.yml`), so regressions in import, servers and settings are found only by hand. Add a test job (Linux is cheapest) once the build works there. | `.github/workflows/windows-build.yml` |
| KI-08 | Low | Upstream sync | The repository was imported as a snapshot without upstream history (`323d8eb`), so upstream security and protocol fixes cannot be merged; they have to be ported by diffing against 5.0.3.1. No record says which upstream commit the snapshot matches. Add it to `ARCHITECTURE.md` §6 when known. | repository |
| KI-09 | Low | Platforms | Only Windows has been built and is being tested. Android, iOS, macOS and Linux keep upstream identifiers (bundle ids, package name `org.amnezia.vpn`, store URLs, installer names) and would publish as Amnezia or collide with it. | `client/cmake/*`, `client/android/`, `client/ios/`, `deploy/` |
| KI-10 | Low | Dead entries | `PageEnum` has entries without a QML file: `PageAbout`, `PageProtocolIKev2Settings`, `PageSettingsLanguage` (inherited). `goToPage` on them would fail. | `client/ui/utils/pageEnum.h` (see `docs/ai/CODE_MAP.md` §5) |
| KI-11 | Low | Translations | Only `amneziavpn_fa_IR.ts` is compiled (`client/CMakeLists.txt`, i18n block); the eleven other `.ts` files stay in source and were touched by `lupdate` in CoCo commits, which inflates diffs. Remove them or stop updating them; never edit them by hand. | `client/translations/`, `client/CMakeLists.txt:80` |
| KI-12 | Medium | SSH security | The SSH client never checks the server's host key: `Client::connectToHost` calls `ssh_connect` and authenticates without `ssh_session_is_known_server` or a fingerprint comparison, so a man in the middle on the first or any later connection gets the password or a session with sudo. Pin the host key (SHA-256 fingerprint stored per server; for webpack servers taken from `/access` `hostKeySha256`). Plan: slice 3 of `docs/plans/W5-buy-vps-in-app.md`. | `client/core/utils/selfhosted/sshClient.cpp:33` |
