# Known Issues and Audit Findings

Audit of `main` at `78f3302` on 2026-11-14 (static review; nothing was built or run). Read the
entries for your area before you change it. When you fix one, delete its row and name the fix in
`CHANGELOG.md`. "Verify" means the finding comes from reading the code and needs a check in the
running app.

| KI-01 | Medium | Amnezia gateway | The default API gateway is still Amnezia's (`http://gw.amnezia.org:80/`). Since the Android port the entry card that listed Amnezia's paid and free services under the CoCo name (`amneziaVpn` in `PageSetupWizardConfigSource.qml`) and "Restore purchases" are hidden, so new users cannot reach them. Still open: servers already imported from the Amnezia API keep using its pages (`PageSettingsApi*`), news and ads; the gateway code is still compiled in. Remove or replace with webpack.ir services (roadmap S4, W6). | `client/core/repositories/secureAppSettingsRepository.cpp:20`, `client/core/controllers/api/*`, `gatewayController.cpp` |
| KI-02 | Medium | Updates | No CoCo update feed exists. The update check is compiled out (`CLIENT_ENABLE_APP_UPDATES 0` in `client/cmake/branding/common.cmake`) and the "Check for updates" button is hidden, so nothing reaches Amnezia's feed today. If it is turned on, it would read `downloadBaseUrl` / `releasePageUrl` from the Amnezia gateway; the macOS / Linux file patterns are still `AmneziaVPN_*` and the App Store id is Amnezia's. CoCo needs its own feed (a signed JSON on `iranux.site` or webpack.ir). | `client/core/controllers/updateController.cpp` |
| KI-04 | Medium | Layering, tests | `ExportUiController` (about 800 lines) mixes persistence of account groups and templates (`Sharing/*` keys), HTML / TXT rendering with tag replacement, file-name rules and batch orchestration inside a UI adapter. None of it has a test. Extract `AccountGroupsRepository`, `ShareTemplateRenderer` (pure, testable) and `AccountBatchController` into `client/core/`, then add Qt tests for rendering and file names. | `client/ui/controllers/selfhosted/exportUiController.*` |
| KI-05 | Medium | Account data | Account groups store each method's full client config in `Sharing/accountGroups` on one device only. They are included in settings backups (`m_fieldsToBackup` has `Sharing/`), but a revoke on the server (`revokeConfig`) or a change from another device does not update the group, so a shared page can show a config that no longer works. Verify. | `exportUiController.cpp`, `client/secureQSettings.h:47` |

Since this PR it skips documentation-only pushes. Decide: trim it to the platforms CoCo ships, or disable it. `tag-deploy.yml` / `tag-upload.yml` are not adapted to CoCo. | `.github/workflows/deploy.yml` |
| KI-07 | Medium | CI | No CI job runs the Qt tests (`AMNEZIA_BUILD_TESTS: OFF` in `windows-build.yml`), so regressions in import, servers and settings are found only by hand. Add a test job (Linux is cheapest) once the build works there. | `.github/workflows/windows-build.yml` |
| KI-08 | Low | Upstream sync | The repository was imported as a snapshot without upstream history (`323d8eb`), so upstream security and protocol fixes cannot be merged; they have to be ported by diffing against 5.0.3.1. The closest upstream tag is `5.0.3.0` (`de93650` in `amnezia-vpn/amnezia-client`; 5.0.3.1 has no tag): the snapshot differs from it in 175 files outside `client/3rd/`, nearly all CoCo branding, Persian and sharing changes. Diff against that tag to port upstream fixes. | repository |
| KI-09 | Low | Platforms | Windows is built and tested; Android now has the CoCo application id `site.iranux.cocovpn` (Kotlin namespace and JNI class names stay `org.amnezia.vpn`) and a CI build (`android-build.yml`), but has not been run on a phone. iOS, macOS and Linux keep upstream identifiers (bundle ids, store URLs, installer names) and would publish as Amnezia or collide with it. The Android release key is not set up yet: without `ANDROID_RELEASE_KEYSTORE_*` secrets the APK is signed with a throwaway key, and each such build cannot update the previous one. | `client/cmake/*`, `client/ios/`, `deploy/`, `.github/workflows/android-build.yml` |

| KI-11 | Low | Translations | Only `amneziavpn_fa_IR.ts` is compiled (`client/CMakeLists.txt`, i18n block); the eleven other `.ts` files stay in source and were touched by `lupdate` in CoCo commits, which inflates diffs. Remove them or stop updating them; never edit them by hand. | `client/translations/`, `client/CMakeLists.txt:80` |
| KI-12 | Medium | SSH security | Servers added by hand still have no host-key check: `Client::connectToHost` compares the host key only when the server carries a pin (`cocoHostKeySha256`, set today only for servers from webpack, from `/access` `hostKeySha256`). For other servers a man in the middle gets the password or a session with sudo. Next step: trust on first use (store the fingerprint at the first successful install and show it), then the same pin check. | `client/core/utils/selfhosted/sshClient.cpp:33` |
| KI-13 | Low | Batch accounts | Every batch step rewrites the whole `Sharing/accountGroups` value (all groups, with each method's config and QR images as base64) through `SecureQSettings` on the GUI thread and emits `accountGroupsChanged`, so a batch of 100 accounts writes O(n²) data and gets slower as the list grows. Coalesce saves (one per account, or a short timer) and store QR codes once per method, or regenerate them from the config when rendering. Verify with 100 accounts × 3 protocols. | `exportUiController.cpp` `persistBatchGroup`, `saveAccountGroups` |
| KI-14 | Low | Android sharing | On Android the save buttons hand the file to the system "create document" picker (`AmneziaActivity.saveFile`), which does not report back: there is no "saved" message, and a write error is only logged. Send the result to Qt (`QtAndroidController`) and show it. | `client/android/src/org/amnezia/vpn/AmneziaActivity.kt` `saveFile`, `PageShare.qml`, `PageSettingsShareTemplates.qml` |
| KI-15 | Medium | DNS tunnel | The DNS tunnel (D1) is installed and connected without a settings page: the resolver is always the first of the config's `resolvers` list, else the network's own DNS, else public DoH (no automatic fallback, because dnstt cannot tell a dead resolver from an idle one), the domain and MTU cannot be changed after install, and its accounts cannot be shared or batch-created (`isShareable` is false). macOS and Linux have no client (`isSupportedByCurrentPlatform`). On Android, CoCo's own app traffic bypasses the VPN while the tunnel is up (the app is excluded so that the `dnstt-client` child process's queries do not loop), and only IPv4 resolvers are used. Next: D1 slices 3 and 4 in `docs/plans/D1-dns-tunnel.md`, plus a protocol page with a resolver list and a "check delegation" button. | `client/core/protocols/dnsttProtocol.cpp`, `client/android/xray/src/main/kotlin/Dnstt.kt`, `client/core/utils/containers/containerUtils.cpp` |
